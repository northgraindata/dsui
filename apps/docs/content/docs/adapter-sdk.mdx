title: Adapter SDK
description: Build, test, and publish a dsui adapter.
---

The SDK is versioned. Bundles declaring any other `sdkVersion` are
rejected before activation. Compatibility is checked before any
adapter code runs.

## Start from the template

Use `templates/adapter`. Model external data as resources, side
effects as actions, and navigation as pages. Validate every input
with Zod and return secret-free errors.

```ts
export default defineAdapter({
  metadata: { id: "example-service", name: "Example Service", version: "0.1.0" },
  connectionSchema,
  context: (config) => ({ endpoint: config.endpoint, token: config.token }),
  resources: [info],
  actions: [ping],
  pages: [overviewPage],
});
```

dsui owns navigation, tables, forms, states, and accessibility.
Adding a new renderer kind requires a dsui core contribution;
adapters never ship browser code.

## Declarative UI boundaries

Pages compose built-in components (tables, buttons, tabs, forms,
inputs, editors) and named composites of them. Descriptors may define
labels, validation, and actions. Adapter React, HTML, CSS, SVG, URLs
beyond `iconUrl`, and browser JavaScript are rejected.

## Package manifest

Ship `dsui.adapter.json`, `dist/adapter.mjs`, a license, and notices.
The manifest declares `resources`, `actions`, and `pages` ids alongside
byte count and SHA-256. The ESM file must contain all dependencies and
may not use native addons or code splitting.

## npm installation

```yaml
adapters:
  example:
    package: "@your-org/dsui-adapter-example"
    version: "0.1.0"
    integrity: "sha512-..."
```

## Test and publish

Cover the adapter with `bun test` against the template's fake-client
pattern, publish from CI with npm provenance, disclose network access
and authentication, and provide a security contact.
