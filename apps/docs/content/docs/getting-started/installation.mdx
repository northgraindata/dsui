## Recommended: npx

The npx installation is the preferred path for local development. It runs DSUI
on the host, so local adapters can use host executables, project directories,
and tools such as dbt Core or dbt Fusion.

Install [Bun](https://bun.sh) 1.3.12 or newer, then run:

```bash
npx dsui
```

DSUI loads `./dsui.yaml` when present and stores local state in
`~/.local/share/dsui`.

## Docker

DSUI ships as a container image on GitHub Container Registry. It needs no separate database or control plane.

```bash
docker pull ghcr.io/northgraindata/dsui:latest
```

```bash
docker run --rm -p 4192:4192 -v dsui-data:/data \
  ghcr.io/northgraindata/dsui:latest
```

This starts an empty workspace. Open `http://localhost:4192` to verify that DSUI
is running, then add `DSUI_CONFIG` and mount a `dsui.yaml` when you are ready to
connect services. The [quickstart](/docs/getting-started/quickstart) shows the
configured path.

The `/data` volume holds DSUI's local state and any file-backed data you mount
there. DSUI does not start the services declared in `dsui.yaml`; it connects to
services that are already running.

Docker is intentionally isolated from the host. The official image includes
the bundled DSUI adapters, but does not include dbt Core or dbt Fusion and
cannot execute a host-only `dbt` binary. Use npx for `dbt local`, or provide a
custom image with the dbt runtime installed.

For a configured workspace with adapters, use the [quickstart](/docs/getting-started/quickstart).

## From source

Contributors can run DSUI from a checkout with Bun `1.3.12`.

```bash
git clone https://github.com/northgraindata/dsui.git
cd dsui
bun install --frozen-lockfile
bun run dev
```
