A signal is a typed event. A plugin declares the signals it publishes, publishes them with `context.events.emit`, and can read the event log, which holds the signals of adapters and plugins. For adapter signals, see [signals](/docs/adapter-sdk/signals).

## Declare and publish a signal

Declare the signal in `setup` with an `id`, a Zod `payload` schema, and a `type` of `info` (the default), `success`, `warning`, or `error`:

```ts
registry.signal({
  id: "ticked",
  payload: z.object({ n: z.number() }),
  type: "info",
});
```

Publish it from a job or a procedure. The optional third argument is the ID of the service that the event is about:

```ts
await context.events.emit("ticked", { n: 7 });
```

DSUI validates the payload against the schema, adds the plugin's ID to the signal as `<plugin id>.ticked`, and stores the event. It then queues the jobs that subscribe to it with `onSignals`. Publishing an undeclared signal throws `Undeclared plugin signal`.

In the event log, a plugin event has `sourceType` set to `plugin` and `sourceId` set to the plugin's ID. See [HTTP API](/docs/reference/http-api#read-events).

## Read events

`context.events.read({ cursor, limit })` returns persisted events in the order they were added, as `{ items, cursor, hasMore }`.

```ts
const page = await context.events.read?.({ limit: 50 });
```

- **`limit`**: from 1 to 500
- **`cursor`**: where to continue. Omit it to replay the available history, or pass `"latest"` to start at the current end
- **`hasMore`**: whether more events follow

To process events once, save the returned `cursor` in plugin storage together with your results, and ignore events that you already handled by their `id`. A page can be empty and still move the cursor forward, because DSUI hides events for services that the caller can't see. Events that belong to no service are visible only to administrators and background jobs. A cursor belongs to one DSUI database, and it isn't a timestamp.

`events.read` is optional. A host that lacks it leaves it undefined, so check that it exists before you rely on it.
