A plugin is a TypeScript package that adds features to the whole workspace. It can add pages and navigation, put content into the interface, run background work, keep its own data, and sign people in. An adapter connects one kind of service. A plugin works across the installation. See [choose adapter or plugin](/docs/build/overview).

A plugin is trusted code. DSUI loads it into the server process, so it can do what the server can do. Only load plugins that you trust.

You write a plugin with the `@northgraindata/dsui-plugin-sdk` package. Pin its exact version. The package re-exports most builtin [components](/docs/build/components), so pages look like adapter pages.

## What a plugin is made of

| Part | What it does | Page |
| --- | --- | --- |
| Pages and navigation | Add screens and links, and Settings entries | [Pages and navigation](/docs/plugin-sdk/pages) |
| Slots and overlays | Add content to the host interface | [Slots and overlays](/docs/plugin-sdk/slots-and-overlays) |
| Resources | Offer reads of data | [Resources](/docs/plugin-sdk/resources) |
| Actions and procedures | Offer validated operations | [Actions and procedures](/docs/plugin-sdk/actions) |
| Jobs | Run durable background work | [Jobs](/docs/plugin-sdk/jobs) |
| Signals | Publish and read events | [Signals and events](/docs/plugin-sdk/signals) |
| Stores and storage | Keep JSON state and SQLite data | [Stores and storage](/docs/plugin-sdk/stores) |
| Host capabilities | Read services and plugins, and check permissions | [Host capabilities](/docs/plugin-sdk/host-capabilities) |
| Providers | Sign people in, and limit what they can do | [Authentication and authorization](/docs/plugin-sdk/auth-providers) |

## Test and share

See [test a plugin](/docs/plugin-sdk/testing) to check your plugin, and [release a plugin](/docs/plugin-sdk/release) to share it. DSUI loads a plugin from a GitHub repository, a directory, or an installed package. See [plugins](/docs/guides/plugins) for how people load one.
